# Проверка рабочей версии YORU — 17.10.2026

Функциональная проверка: релиз `9d989199-ce51-4736-8027-4cc8cc069167`. Текущая проверенная версия интерфейса: релиз `f3aef160-e08f-440c-81b6-4cfc6ff15bea`, код `968875c`.

## Подтверждено

- 55 автоматических тестов, все проходят. `npm audit --omit=dev`: 0 известных уязвимостей зависимостей.
- Обычный пользователь и модератор получают 403 на чтение и изменение админских маршрутов, включая другой регистр URL. Изменение роли применяется к существующей сессии сразу.
- Модератор может скрывать комментарии, обычный пользователь — нет. Скрытый комментарий исчезает из обсуждения. HTML комментария отображается текстом, спойлер закрыт details.
- Режим Telegram-only запрещает почтовые формы/записи и для `/REGISTER/`, `/LOGIN/`. Проверены официальный redirect, PKCE S256, привязка state к браузеру, отказ на отсутствующую/истёкшую привязку. Подпись токенов проверяет jose. Свежий полный вход через личный Telegram пользователя в этой проверке не выполнялся; ранее владелец подтвердил работу входа.
- Динамические страницы отдаются no-store, история/библиотека/уведомления принадлежат текущему пользователю, CSRF обязателен для изменений. Большой upload возвращает 413, плохие данные формы 400, отсутствующие сущности 404.
- Блокировка сохраняет страницу, убирает плеер, даёт 403 обоим provider API, status и записи просмотра. Интеграционные тесты отдельно блокируют тайтл во время удалённого lookup: URLs не выдаются. На публичном сайте проверены block/unblock на временном тайтле.
- Последняя завершённая серия не приводит к resume более старой незавершённой серии. Ручные отметки/снятие, сезоны, уникальная статистика и особые статусы библиотеки проверены тестами прошлых этапов и регрессиями.
- На локальной новой версии фактически воспроизведён HLS с сохранённой позиции; проверены подписки, уведомления, мобильная ширина.
- Публичная ролевая проверка с настоящей PostgreSQL прошла; использованы только временные аккаунты/тайтл, затем удалены вместе с комментариями, сеансами, личной историей и их аудитом.
- Свежий публичный запуск синхронизации `6113c6b1-17d8-4a39-a590-30b781b096ec`: done, первая попытка, 40 релизов, 0 ошибок, 0 дублей, все 552 старые даты неизменны. Результат оставлен в админке как реальное задание обслуживания.
- Старый тестовый failed job с фиктивным ID 2000000001 удалён. Два существующих задания ID 121496 с ответом Shikimori 404 сохранены для проверки исходного ID; наличие этих ошибок видно администратору.

## Исправления этого этапа

Нормализация aliases для AUTH_MODE; корректный выбор resume обоих API; no-store; лимит старта OAuth; часовая очистка истёкших sessions/oauth_flows/email_tokens; валидация даты и JSON ручного импорта; корректные 400/404/413 и отсутствие ложного аудита при несуществующей цели.

## Границы текущей версии

- Основной этап дизайна/вёрстки завершён и проверен на ПК и телефоне. Уникальные переписанные описания отложены владельцем.
- Почта отключена; уведомления о сериях только внутри сайта, Telegram-рассылки нет.
- Лента перевода относится к доступной библиотеке AniLiberty, до 40 последних релизов за проверку. Дата — обновление источника/первое обнаружение, не гарантированная дата публикации. Японский эфир из Shikimori не равен выходу перевода.
- Китайские тайтлы имеют ручную/защищённую классификацию: Shikimori не даёт надёжной страны для автоматического разделения.
- Ограничения стран/прав провайдеров соблюдаются. Реальный Kodik в проверочном браузере ранее показывал запрет по стране; гарантии его воспроизведения во всех регионах нет.
- Один процесс web/worker. Блокировки задач/лимиты не рассчитаны на горизонтальное масштабирование без отдельной доработки.
- Ежедневные приватные логические backups и восстановление проверены отдельно, инструкция `ops/backup/README.md`. PITR не включён; окно между копиями до суток. Код восстановления не доступен через сайт.

Эта проверка фиксирует выполненные сценарии и обнаруженные ограничения; она не является обещанием отсутствия всех возможных ошибок.

После развёртывания новой версии на публичном сайте дополнительно подтверждено настоящее воспроизведение HLS после resume с 30-й секунды; на управляемом status-ответе подтверждена остановка video. Финальная проверка очистки: временных пользователей и тайтлов 0, рабочий health 200.
