# Автопарсинг YORU

## Состояние выпуска

Код подготовлен локально. В текущей сессии сетевые соединения запрещены: DNS внешних адресов возвращает ENOTFOUND, HTTP-тесты с localhost — EACCES. Поэтому миграция 008 ещё не применена к Railway, новые задания в рабочей БД не запускались, массовое наполнение и настоящие запросы новых адаптеров не проверены. Не считать каталог уже наполненным.

## Возможности

В `/admin/autoparse` администратор настраивает начальный/конечный год, форматы, статусы, время ежедневного обхода по МСК, страницы за день, интервалы обновления и постеров, источники серий. Настройки, текущий год/страница и следующие запуски хранятся в PostgreSQL. Доступ защищён requireAdmin и общим CSRF middleware.

По умолчанию: 1998 — текущий год включительно; ТВ, фильмы, OVA, ONA, спецвыпуски; завершённые, онгоинги и анонсы. Архив стартует в 03:00 МСК, максимум 20 страниц в день, до 50 тайтлов на странице. Лимит можно изменить до 100 страниц. Начать раньше можно кнопкой «Запустить сейчас» у наполнения. Повторный обход не удаляет старые записи и не объединяет сезоны с одинаковыми названиями.

Архив идёт по годам и стабильной сортировке ID. Страница фиксируется после успешного прохода; ошибки повторяются с прежней позиции. При 100 незавершённых импортах новые страницы ждут. Из списка сначала добавляются базовые сведения, полные описания/участники/кадры догружаются очередью. Уникальный Shikimori ID защищает тайтлы от копий, транзакционный auto_job_keys защищает повторную постановку заданий. Текущие онгоинги/анонсы и последние завершённые обнаруживаются отдельно — не ждут, пока архив дойдёт до текущего года.

Для автоматического расписания нужны AUTO_SYNC=true и работающий worker (WORKER_ENABLED не false). Глобальная пауза останавливает постановку и взятие автоматических задач, уже выполняющийся проход заканчивает свою порцию. Настройки отдельных задач применяются к следующему проходу. Ручные обычные импорты остаются доступны. Один процесс worker; горизонтальное масштабирование без отдельного распределённого планировщика не поддерживается.

## Источники серий

- AniLiberty: готовые доступные переводы, существующий механизм сохраняется.
- Shikimori: рост episodes_aired означает оригинальный эфир. В ленте/уведомлении явно стоит «эфир»; это не обещание наличия перевода. Ссылка открывает Kodik, который отдельно проверяет доступность.
- Kodik: адаптер полного каталожного `/list`, только с личным KODIK_API_TOKEN в переменных Railway. Публичный ключ get-player не используется вместо каталожного. Без личного ключа задача выключена, попытка включить отклоняется. Контракт проверен на тестовых ответах; реальная работа с личным ключом пока не подтверждена. Обрабатываются только точные Shikimori ID из существующего каталога и материалы с разрешённым публичным встраиванием; многосезонные записи не угадываются.

Первое наблюдение каждого источника фиксирует базовый счётчик без массовых уведомлений о старых сериях. Рост сохраняется один раз, повторы не меняют дату. Лента содержит один тайтл: максимальную серию, при равной серии предпочитает готовый источник. Между источниками уведомление одной серии не дублируется. Блокировки и отсутствие подписки учитываются.

## Постеры

Резерв — MyAnimeList через [Jikan v4](https://docs.api.jikan.moe/). Совпадение ID само по себе недостаточно: требуется оригинальное название и, когда год тайтла известен, совпадающий год. URL допускается только HTTPS cdn.myanimelist.net. Чужая картинка при несовпадении не подставляется.

Защищённый ручной poster не меняется. Защита перепроверяется под блокировкой строки после обращения к сети. Подтверждённый резерв сохраняется при обычном обновлении Shikimori; проверка повторяется раз в неделю. По умолчанию 20 постеров каждые 30 минут, запросы ограничены примерно одним в секунду. При ошибке API прежний постер сохраняется. Битый HTTP-ответ изображения на странице заменяется нейтральным «Постер ожидается» с прежней геометрией.

Картинку-заглушку, отдаваемую источником с HTTP 200, браузерный onerror распознать не может; её устраняет подтверждённая резервная картинка. Для тайтлов без достоверного соответствия остаётся ручная замена в редакторе.

## Проверка и публикация владельцем

В обычном PowerShell из папки проекта:

```powershell
& 'C:\Program Files\nodejs\node.exe' --test --test-concurrency=1
# Только если все тесты прошли:
& "$env:APPDATA\npm\railway.cmd" up --service web --detach
```

Сервер применяет 008_autoparse.sql при запуске. После успешного деплоя: открыть «Управление сайтом → Автопарсинг», проверить 1998/конечный год, время и лимиты, сохранить. Нажать «Запустить сейчас» у архива и постеров. Следить за годом/страницей, очередью импорта и результатами. Не запускать второй локальный worker против той же рабочей БД.

Затем нужны настоящие проверки: первая страница 1998, повтор без дублей, рестарт с продолжением, следующий запланированный запуск, несколько заменённых постеров, новые эпизоды каждого активного источника. При проблеме выключить автоматический обход; существующие страницы и ручная админка продолжают работать.

Локально прошли 18 тестов источников/нового планировщика, две прежние проверки импорта/воркера и проверка безопасной цели восстановления (всего 21). Статическая админ-страница проверена в браузере 320/390/768/1440 px без подключения к HTTP-серверу. Полный HTTP-набор в этой сессии не выполнен из-за запрета localhost, а не объявлен успешным.
