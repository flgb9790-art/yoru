# Автопарсинг YORU

## Состояние выпуска

Изменения подготовлены локально. Выполнены локальные HTTP/модульные тесты и браузерные проверки. 19.10.2026 справочник жанров и выборка по Исэкай дополнительно проверены чтением живого публичного API Shikimori. Импорт в рабочую базу, очистка рабочего каталога и production-деплой не выполнялись.

## Возможности

В `/admin/autoparse` администратор настраивает начальный/конечный год, форматы, статусы, время ежедневного обхода по МСК, страницы за день, интервалы обновления и постеров, источники серий. Настройки, текущий год/страница и следующие запуски хранятся в PostgreSQL. Доступ защищён requireAdmin и общим CSRF middleware.

По умолчанию: 1998 — текущий год включительно; ТВ, фильмы, OVA, ONA, спецвыпуски; завершённые и онгоинги. Архив стартует в 03:00 МСК, максимум 20 страниц в день, до 50 тайтлов на странице. Лимит можно изменить до 100 страниц. Начать раньше можно кнопкой «Запустить сейчас» у наполнения. Повторный обход не удаляет старые записи и не объединяет сезоны с одинаковыми названиями.

Архив идёт по годам и стабильной сортировке ID. Страница фиксируется после успешного прохода; ошибки повторяются с прежней позиции. При достижении настроенного лимита очереди (по умолчанию 100) новые страницы ждут. Из списка сначала добавляются базовые сведения, полные описания/участники/кадры догружаются очередью. Уникальный Shikimori ID защищает тайтлы от копий, транзакционный auto_job_keys защищает повторную постановку заданий. Текущие онгоинги и последние завершённые обнаруживаются отдельно — не ждут, пока архив дойдёт до текущего года.

Для автоматического расписания нужны AUTO_SYNC=true и работающий worker (WORKER_ENABLED не false). Глобальная пауза останавливает постановку и взятие автоматических задач, уже выполняющийся проход заканчивает свою порцию. Настройки отдельных задач применяются к следующему проходу. Ручные обычные импорты остаются доступны. Один процесс worker; горизонтальное масштабирование без отдельного распределённого планировщика не поддерживается.

## Отбор и обязательные правила

Панель разделена на три секции: «Какие аниме добавлять», «Когда и сколько парсить», «Серии и постеры». В основной секции доступны годы, страны, форматы, статусы, нужные жанры (хотя бы один / все одновременно) и дополнительные исключения. Список жанров берётся из каталога; дополнительные названия можно вписать через запятую. Дополнительные условия: минимальный рейтинг Shikimori, диапазон серий и длительности в минутах, возрастной рейтинг, часть названия и студии. Ноль выключает числовое ограничение. Неизвестное число/длительность не проходит заданный соответствующий предел. Пустой список стран/жанров/возрастных рейтингов не ограничивает выбор.

Краткий REST-список Shikimori не содержит жанры. Перед сохранением страницы выполняется пакетная проверка метаданных GraphQL по точным ID. Ошибка или неполный ответ не продвигает курсор. В `origin` Shikimori хранится первоисточник (манга, роман и т. п.), а не страна. Для страны используется явный ISO-код `countryOfOrigin` AniList: соответствие проверяется по MAL ID, оригинальному названию и году. Подтверждённые совпадения кешируются на 12 часов, отсутствующие — на час. Без подтверждения ставится «Не определена», а не «Япония». Если страна выбрана, ошибка AniList оставляет страницу на повтор; при любом выборе стран неподтверждённый тайтл не проходит фильтр. Без ограничения стран допускается неизвестная страна. Ранее подтверждённая страна не стирается временной ошибкой обновления.

Импорт использует только непустое `russian` Shikimori; подстановка английского/оригинального названия удалена. Оригинальное название отдельно сохраняется для поиска и проверки соответствий. Официальные названия вроде «86» допустимы, если заполнено поле `russian` источника.

Всегда запрещены **Детское, Авангард, Антропоморфизм, Хентай, Яой**, включая английские соответствия Kids, Avant-Garde, Anthropomorphic, Hentai, Yaoi. Запрет применяется к жанрам и исходным метаданным до сохранения, к ручному редактору жанров, полному импорту, AniLiberty и восстановлению жанров. Защита ручных полей запрет не отключает. При запуске обновлённого сервера и автоматическом проходе уже добавленные тайтлы с этими жанрами удаляются из каталога вместе со связанными записями. Полный снимок, комментарии, реакции, библиотека и история сохраняются в `deleted_anime.snapshot`; отправленные в чат названия аниме остаются с пометкой недоступности. ID исключается из повторного импорта. На панели есть суммарный счётчик «Исключено жанрами».

Страны/жанры и остальные дополнительные условия управляют автоматическим добавлением и очередью автоматического полного импорта; явный ручной импорт по ID может выйти за эти дополнительные условия, но обязательные запреты и русское название действуют всегда. Изменение условий сбрасывает архив на начало нового отбора; изменение только времени не сбрасывает курсор. Автоматические задания из старой очереди перепроверяют актуальные условия. Лимит очереди теперь настраивается (20–1000). Список задач сворачивается отдельно, состояние раскрытых блоков не теряется при опросе прогресса. Для пропущенных записей показываются причины.

Схема Shikimori: [краткий сериализатор](https://github.com/shikimori/shikimori/blob/master/app/serializers/anime_serializer.rb), [значения origin](https://github.com/shikimori/shikimori/blob/master/app/models/types/anime.rb). Страны: [AniList Media](https://docs.anilist.co/reference/object/media), [пакетный поиск Page](https://docs.anilist.co/reference/object/page).

## Источники серий

- AniLiberty: готовые доступные переводы, существующий механизм сохраняется.
- Shikimori: рост episodes_aired означает оригинальный эфир. В ленте/уведомлении явно стоит «эфир»; это не обещание наличия перевода. Ссылка открывает Kodik, который отдельно проверяет доступность.
- Kodik: адаптер полного каталожного `/list`, только с личным KODIK_API_TOKEN в переменных Railway. Публичный ключ get-player не используется вместо каталожного. Без личного ключа задача выключена, попытка включить отклоняется. Контракт проверен на тестовых ответах; реальная работа с личным ключом пока не подтверждена. Обрабатываются только точные Shikimori ID из существующего каталога и материалы с разрешённым публичным встраиванием; многосезонные записи не угадываются.

Первое наблюдение каждого источника фиксирует базовый счётчик без массовых уведомлений о старых сериях. Рост сохраняется один раз, повторы не меняют дату. Лента содержит один тайтл: максимальную серию, при равной серии предпочитает готовый источник. Между источниками уведомление одной серии не дублируется. Блокировки и отсутствие подписки учитываются.

## Постеры

Резерв — MyAnimeList через [Jikan v4](https://docs.api.jikan.moe/). Совпадение ID само по себе недостаточно: требуется оригинальное название и, когда год тайтла известен, совпадающий год. URL допускается только HTTPS cdn.myanimelist.net. Чужая картинка при несовпадении не подставляется.

Защищённый ручной poster не меняется. Защита перепроверяется под блокировкой строки после обращения к сети. Подтверждённый резерв сохраняется при обычном обновлении Shikimori; проверка повторяется раз в неделю. По умолчанию 20 постеров каждые 30 минут, запросы ограничены примерно одним в секунду. При ошибке API прежний постер сохраняется. Битый HTTP-ответ изображения на странице заменяется нейтральным «Постер ожидается» с прежней геометрией.

Картинку-заглушку, отдаваемую источником с HTTP 200, браузерный onerror распознать не может; её устраняет подтверждённая резервная картинка. Для тайтлов без достоверного соответствия остаётся ручная замена в редакторе.

Сервер применяет актуальные миграции и обязательные правила каталога при запуске. После успешного деплоя: открыть «Управление сайтом → Автопарсинг», проверить 1998/конечный год, время и лимиты, сохранить. Нажать «Запустить сейчас» у архива и постеров. Следить за годом/страницей, очередью импорта и результатами. Не запускать второй локальный worker против той же рабочей БД.

Затем нужны настоящие проверки: первая страница 1998, повтор без дублей, рестарт с продолжением, следующий запланированный запуск, несколько заменённых постеров, новые эпизоды каждого активного источника. При проблеме выключить автоматический обход; существующие страницы и ручная админка продолжают работать.

Локально прошли 52 pure/DB теста и отдельная проверка добавления нового тайтла из ленты серий. Панель проверена на реальных обработчиках с pg-mem и перехватом запросов в браузере: обе темы, ширина 320/390/768/1440/2560 px, сохранение настроек, валидация и обновление прогресса. Полный HTTP-набор, реальные запросы к API и деплой в этой среде не выполнены.

### Состояние обхода и исключение анонсов

Версия с миграцией 009 показывает обновляемую панель состояния (каждые 5 секунд), текущую порцию, очередь импорта, длительность и связь с worker. Прогресс относится к порции, общий размер каталога заранее неизвестен. При старте удаляются ещё не выходившие анонсы (status=anons, aired=0), предварительно сохраняемые в removed_announcements. Записи с доступными релизами или фактическим просмотром сохраняются для проверки ошибочного статуса. Новые анонсы отклоняются общим импортом. После деплоя проверить панель и результат очистки; локальный полный HTTP-набор в ограниченной среде недоступен.


## Очистка качества каталога

При старте и автоматическом проходе удаляются с архивированием тайтлы без русского названия, с рейтингом Shikimori 0, без постера или с известным адресом заглушки. Для старых записей без исходного рейтинга используется сохранённый rating; новый импорт сохраняет shikimori_score отдельно. Удалённые ID не возвращаются при импорте. Опция «Только с постером без заглушки» включена по умолчанию; её отключение разрешает пустые постеры и отключает соответствующую очистку, но не восстанавливает ранее удалённое. Русское название обязательно, нулевой рейтинг автоматический импорт не проходит. Минимальный ненулевой рейтинг остаётся настраиваемым.

Определяются пустой URL и известные пути missing/no-image/no-poster/placeholder/questionmark/404. Произвольная картинка-заглушка с обычным URL и HTTP 200 не распознаётся по пикселям; сетевой аудит изображений не выполнялся.

Фильтр «Только с сериями» (requireEpisodes) включён по умолчанию: исключает тайтл, если episodes и aired не больше нуля. Онгоинг с неизвестным общим числом, но известными вышедшими сериями сохраняется. Условие применяется к автоматическому импорту и очистке каталога, входит в ключ отбора. Удаление архивируется и блокирует повторный импорт ID. Отключение фильтра не восстанавливает удалённое.


## Независимое наполнение по жанрам

В начале `/admin/autoparse` расположен блок «Загрузить по жанрам сейчас». Это отдельная очередь, которую не останавливает переключатель основного автопарсинга и которая не ждёт его задания. Нужен работающий worker (`WORKER_ENABLED` не `false`); `AUTO_SYNC=true` для ручного наполнения не требуется.

1. Выбрать один или несколько жанров/тем. Справочник берётся из Shikimori GraphQL `genres(entryType: Anime)` (включая Исэкай и Реинкарнацию), хранится в PostgreSQL сутки и обновляется кнопкой. Запрещённые жанры не предлагаются. Если источник недоступен, показан явно отмеченный сохранённый справочник; при первом подключении без справочника запуск недоступен.
2. Задать страну, годы, минимальный рейтинг и количество **новых** тайтлов (1–1000, по умолчанию50). Уже имеющиеся тайтлы лимит не расходуют. По умолчанию1900–текущий год, рейтинг6, любые страны и основные форматы.
3. При необходимости раскрыть дополнительные условия: сортировка, формат, статус и часть названия. Режим жанров — любой выбранный либо все одновременно.
4. Нажать «Запустить сейчас». В очереди видны добавленные/запрошенные тайтлы, ожидающие, существующие, пропущенные и ошибки; текущая операция/название, шкала и раскрываемый список с причинами. Опрос3сек. Форму можно заполнять во время работы; опрос её не перерисовывает. До5 незавершённых запусков, обслуживаются по порядку, приостановленный не блокирует следующий.

Пауза/продолжение/остановка доступны отдельно для каждого запуска. Выполняющийся запрос может завершиться, но перед сохранением тайтла и следующей страницей состояние проверяется заново. Остановка отменяет ожидающие записи, уже добавленные аниме остаются. При сетевом сбое до3 повторов с паузой; после ошибки страницы курсор не продвигается, продолжение возобновляет сохранённое место. После исчерпания источника запуск завершается, даже если найдено меньше требуемого количества.

Отбор снимком сохраняется в `manual_parse_runs`, тайтлы/результаты — в `manual_parse_items` (миграция019). Фоновая задача делает короткие шаги отдельно от расписания; lease с heartbeat не позволяет одновременно обрабатывать один запуск в двух процессах и восстанавливается после аварии. Уникальные run+Shikimori ID и idempotency-ключ формы предотвращают дубли. Импорты используют общую защиту уникального ID в каталоге. Данные загружаются полностью, без промежуточных карточек-заготовок; перед записью повторно проверяются выбранные условия, русский заголовок, настоящий адрес постера, серии, ненулевой рейтинг, запреты и ранее удалённые ID. Обновление серий сохраняет собственную очередь. Общий последовательный лимитер Shikimori сохранён; параллельный поток не означает обход ограничений API. Для всего приложения по-прежнему рекомендуется один worker.

Для поиска используется современный `genre_v2` (старый `genre` не содержит современных тем), условия повторно проверяются по пакетным GraphQL-метаданным; страна — по подтверждённому AniList соответствию. Для «любой жанр» списки каждого жанра объединяются и очищаются от дублей; для «все жанры» источник ограничивается первым и пересечение проверяется локально. Защитный предел1000страниц на запуск.

Настройки ручного запуска не изменяют основной отбор. Публичное меню и фильтр теперь показывают жанры **фактически добавленных**, незаблокированных, неанонсированных аниме независимо от выбора любого парсера. Один лишь выбор темы в админке не создаёт пункт в меню. После импорта кеш сбрасывается в текущем процессе; в других процессах обновляется не позднее30сек. Постоянные запреты действуют и здесь.

Параметры REST подтверждены [исходным контроллером Shikimori](https://github.com/shikimori/shikimori/blob/master/app/controllers/api/v1/animes_controller.rb). Для проверки использовались публичные запросы `/api/graphql` и `/api/animes?genre_v2=130`; приватные ключи для чтения справочника не нужны.
