# Редактор оформления YORU

Открывается администратору: «Управление сайтом → Редактор оформления», адрес `/admin/design`.

Доступны 13 файлов: общий шаблон/карточки/фильтр, страница аниме, профиль, расписание, подборки, четыре CSS-файла и четыре браузерных JS-файла. Серверные настройки, вход, база, парсеры, секреты и код самого редактора не входят в список.

Слева выберите файл. Есть подсветка кода, номера строк, Tab, поиск/замена одного совпадения, перенос строк, Ctrl/Cmd+S и Ctrl/Cmd+F. При уходе с несохранёнными изменениями браузер просит подтверждение. История хранит предыдущие версии: загрузите нужную в редактор и нажмите «Сохранить». «Версия деплоя» возвращает исходный файл в буфер; применение также требует сохранения.

CSS и браузерный JavaScript применяются после обновления страницы сайта. Изменённые серверные шаблоны (`src/…`) применяются после перезапуска сервиса web через Railway. Проверка JavaScript перед сохранением проверяет синтаксис, а не правильность поведения страницы. Если импорт изменённых шаблонов ломает запуск, исходные шаблоны возвращаются, а неудачная версия остаётся в истории; следующий автоматический запуск использует исходные файлы. Если ошибка проявляется при открытии страницы, прямой адрес `/admin/design` использует отдельную оболочку для восстановления.

Миграция 010 добавляет `design_files` и `design_revisions`. Изменения сохраняются в PostgreSQL и восстанавливаются перед импортом приложения при старте контейнера Railway; в Git автоматически не отправляются. Если файл в новом деплое отличается от исходной версии редактора, старая правка не применяется молча. В редакторе появится конфликт: сравните сохранённый код с «Версией деплоя» и явно подтвердите применение поверх обновления либо сохраните актуальную версию деплоя. После восстановления исходного содержимого переопределение отключается.

В этой сессии выполнены проверки pg-mem/файловой системы и Playwright с подставленными HTTP-ответами. Настоящий HTTP-набор, PostgreSQL на Railway и деплой из ограниченной среды не выполнялись.
