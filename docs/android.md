# Android YORU

Android 8+ (API26), package `app.yoru.android`, Java17, compile/target35. WebView отображает действующий сайт, поэтому библиотека, чат, каталог и большинство исправлений обновляются вместе с сайтом. Нужен интернет. Первый APK без google-services.json работает с сайтом, но не получает push.

## Подключение Firebase

1. В https://console.firebase.google.com/ создайте проект. Google Analytics для этой реализации не требуется.
2. Добавьте Android-приложение с package **app.yoru.android**, имя YORU. Для FCM SHA сертификата не требуется.
3. Скачайте **google-services.json** в `android/app/google-services.json`. Это конфигурация Android-клиента, не серверный ключ. Gradle читает appId/projectId/apiKey/senderId; Google Services plugin не нужен. Не подставляйте выдуманные значения. Если package отличается, сборка остановится.
4. В настройках проекта → Cloud Messaging проверьте включение Firebase Cloud Messaging API HTTP v1. Устройство должно иметь Google Play services и актуальный Android System WebView.
5. В настройках проекта → Service accounts создайте серверный private key JSON. Он нужен только серверу. Добавьте **всё содержимое JSON** в Railway Variables сервиса web как `FIREBASE_SERVICE_ACCOUNT_JSON`. Не кладите этот ключ в android/app/, public/, APK или Git и не отправляйте его в переписку. Рабочий процесс, в котором запущен startWorker, должен получить эту переменную. При WORKER_ENABLED=false push worker тоже отключён; тогда переменная нужна отдельному worker.
6. Разверните сервер с миграцией018 и public/android.js. Соберите APK повторно после добавления google-services.json. Откройте приложение, войдите и разрешите уведомления. После подключения начальная история не рассылается.
7. Двумя аккаунтами проверьте: новое сообщение в свёрнутом приложении, переход в диалог, выход/смена аккаунта, отключение каналов в настройках Android. Для серии подпишитесь на ongoing до появления новой серии, затем проверьте реальное обновление парсером.

Firebase JSON Android и серверный service account должны принадлежать одному проекту. Аналитика в приложении отключена. Политика /privacy дополнена фактической обработкой push-данных.

## Сборка

Из корня репозитория в PowerShell7:

```powershell
./android/build.ps1
```

Скрипт использует JAVA_HOME и ANDROID_HOME/ANDROID_SDK_ROOT. В текущем рабочем окружении также подхватывает инструменты в соседнем work/: JDK17, SDK35 и build-tools35.0.0. Кэши/служебные файлы остаются в work/. Gradle wrapper8.11.1 включён в репозиторий, AGP8.9.2.

Результат: `artifacts/YORU-release.apk`, подписан локальным ключом. При первой release-сборке скрипт создаёт `android/yoru-release.jks` и `android/keystore.properties` со случайным паролем. **Сохраните обе записи в приватном резервном хранилище**: обновления уже установленного APK требуют того же ключа. В Git и Docker эти файлы не попадают. Не удаляйте ключ между сборками. Не используйте debug-подпись для распространяемой версии.

```powershell
./android/build.ps1 -DebugApk
./android/build.ps1 -Verify
# При необходимости полной пересборки:
./android/build.ps1 -Verify -Clean
./android/build.ps1 -SiteUrl 'https://your-domain.example'
cd android
./gradlew.bat testDebugUnitTest lintDebug
```

SiteUrl — HTTPS origin без пути, логина и пароля. При изменении домена пересоберите приложение: канал WebMessage намеренно разрешает только этот origin. Для следующего релиза увеличьте versionCode в android/app/build.gradle, сохраните package и ключ.

Для установки передайте APK на телефон и разрешите установку для приложения, которым открываете файл. Публикация в Google Play и учётная запись разработчика не входят в текущую сборку.

## Возможности и ограничения

- Сессии/cookies сохраняются между запусками. Telegram OAuth открывается в том же WebView, чтобы callback получил cookie; прочие внешние ссылки открываются отдельно.
- Системная кнопка Назад закрывает диалог/полноэкранный плеер либо возвращает по истории. Галерея через системный выбор файла без доступа ко всему хранилищу.
- Fullscreen WebChromeClient, поворот плеера, управление системными inset/IME. Ошибка основного запроса показывает экран повтора. Видео и вход необходимо проверить на реальном устройстве с выбранными провайдерами.
- Изолированный WebMessage listener только для главного фрейма origin сайта. Нет addJavascriptInterface, доступа к file://, обхода SSL или cleartext HTTP. Серверный ключ в APK отсутствует.
- FCM получает data-only сообщения: приложение проверяет account_id и само показывает уведомление в каналах «Сообщения» и «Новые серии», с PRIVATE видимостью на экране блокировки. Превью передаются через Google; это не E2EE. Изображения из сообщений в push не передаются.
- Разрешение уведомлений запрашивается после входа при настроенном Firebase. Настройки Android можно открыть из собственного профиля в приложении. Каналы можно отключать независимо.
- Доставка при свёрнутом/выгруженном приложении обеспечивается FCM, но не гарантируется после принудительного «Остановить» в настройках Android, без Play services, интернета или разрешения. Ограничения производителя/энергосбережения также влияют; в таком случае откройте приложение снова.
- Ротация FCM-токена запускает системную сетевую JobScheduler-задачу с повтором даже без открытого экрана. Она использует cookie текущего WebView, перепроверяет аккаунт и CSRF; серверные ключи не требуются на телефоне.
- Worker раз в5сек обрабатывает устройства с lease, курсорами и backoff. Непрочитанные события за24ч; сообщения скрытые/удалённые, прочитанные и blocked-аниме пропускаются. После выхода/истечения сессии отправки прекращаются. Старая история при новой привязке не отправляется. При сбое между FCM-send и сохранением cursor возможна повторная доставка, но стабильный notification tag заменяет прежнее уведомление того же события.
- Серии используют существующую систему отслеживания и уведомления парсера. Для получения нужно «Отслеживать» аниме; общая библиотека не равна подписке на все серии.

## Проверка

Node-тесты `test/android-push.test.js`: регистрация/ротация/секрет, привязка к аккаунту/сессии, baseline/cursors, unread/скрытие/удаление/блокировка, retries/leases, logout/expired tokens, OAuth и data-only FCM с подменой транспорта. JVM тест UrlPolicy защищает переходы из уведомлений. Без настоящего Firebase успешная live-доставка не может быть подтверждена.

Официальные источники: https://firebase.google.com/docs/android/setup, https://firebase.google.com/docs/cloud-messaging/android/get-started, https://firebase.google.com/docs/cloud-messaging/send/v1-api, https://developer.android.com/build/releases/agp-8-9-0-release-notes.
