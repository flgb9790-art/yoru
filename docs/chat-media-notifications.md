# Картинки чата и уведомления рабочего стола

## Уведомления

На страницах вошедшего пользователя загружается desktop-notifications.js. Всплывающие окна работают при ширине от900px с hover и точным указателем. Первое обращение к /api/live-events фиксирует текущую позицию без старых уведомлений. Отдельные монотонные последовательности сообщений, серий и ответов позволяют получать пачки по20 без дублей при одинаковом времени. API выбирает только события адресата; превью сообщения максимум180символов, HTML создаётся через textContent.

Справа снизу до3 одинаковых окон360×112px, остальные ждут в ограниченной очереди. Каждое показанное окно живёт15сек или до закрытия/перехода; при выходе и на мобильной ширине убирается. Есть постер/аватар, категория, название и двухстрочное превью. На текущем активном диалоге первой страницы у нижнего края повторный popup и звук не выдаются. Источники оригинального эфира подписаны отдельно. Сообщения не добавляются в колокольчик.

Звук — оригинальный короткий мягкий двухтональный синусный сигнал Web Audio, а не файл из приложения ChatGPT. Браузер разрешает его после взаимодействия со страницей. В профиле есть переключатель; предпочтение хранится в localStorage. Это уведомления открытого сайта, не push при закрытом браузере. Между несколькими открытыми вкладками синхронизация звука не реализована.

## Картинки

Кнопка изображения и вставка файла из буфера в поле сообщения. По одной картинке на сообщение, можно с подписью и аниме. Перед отправкой браузер уменьшает сторону до2048px, перекодирует в WebP, удаляя исходные метаданные. Исходный файл до12МБ/25МП. Сервер независимо проверяет размер до3МБ, сигнатуру и размеры PNG/JPEG/WebP, не принимает SVG/GIF и не доверяет расширению. Обработка изображения полностью на стороне браузера; сервер не является полноценным декодером формата.

Миграция016: message_images хранит BYTEA, MIME, размер и срок; direct_messages — срок и хеш для повторной отправки без дубля. Вставка сообщения и файла транзакционная. Сериализованная проверка квоты:20МБ активных файлов на отправителя,80МБ на все файлы чата,30 запросов загрузки/IP/час. Это лимит полезных байтов вложений, а не точный размер PostgreSQL с индексами/WAL/резервами.

/chat-images/:id проверяет участие в диалоге и срок, даже администратор не получает чужую картинку через этот endpoint. Cache-Control:no-store и nosniff. После7дней сервер сразу перестаёт отдавать файл; hourly cleanupExpired работающего worker удаляет бинарные строки. На месте картинки остаётся текст о сроке, само сообщение сохраняется. Физическое освобождение страниц БД зависит от PostgreSQL, копии в бэкапах — от ротации; удаление не отзывает уже скачанные получателем файлы.

## Верстка

Единая аккуратная SVG-иконка чата используется в мессенджере и друзьях, обновлён значок отправки. Исправлена высота chat-thread: старое max-height680px из theme.css вызывало переполнение и потерю нижнего padding. На последнем сообщении остаётся24–30px. Загрузка изображений удерживает конец ленты; wheel/touch/pointer вмешательство прекращает автопрокрутку.

## Проверки и ограничения

67 pure/DB/route тестов прошли. Новые4: валидация, квоты/rollback/идемпотентность, срок/удаление, доступ участников, отдельные event cursors и пачка25 событий без дублей. Playwright на реальных обработчиках с перехватом HTTP: одинаковые popup, кнопка закрытия,15сек исчезновения, запуск Web Audio после жеста, обе темы320/390/1440, загрузка/перекодирование/отправка и paste через ClipboardEvent, отсутствие overflow и геометрический зазор>=20px после последнего сообщения. Снимки уведомлений и мобильного чата просмотрены.

pg-mem повреждает двоичные параметры BYTEA (подтверждено отдельным минимальным примером), поэтому браузерный адаптер теста хранит ASCII-заглушку вместо бинарного параметра и возвращает оригинальный байтовый буфер только после успешного вызова настоящего защищённого обработчика. Это ограничение QA; production хранит обычный Buffer через pg. Полный HTTP/Multer-прогон и реальная PostgreSQL/Railway проверка в этой среде не выполнялись. Перед публикацией нужен полный node --test --test-concurrency=1 и проверка отправки двух настоящих аккаунтов. Деплой не выполнялся.
